# Библиотека гайдов: структура и план развития

Обновлено: 18 августа 2026.

Этот файл фиксирует текущую архитектуру библиотеки гайдов srumyantsev.ru и рабочий план её развития. Использовать как ориентир при выборе тем, распределении новых материалов по ступеням и категориям, внутренней перелинковке и развитии SEO-кластеров.

## 1. Задача библиотеки

Библиотека не должна превращаться в склад статей о нейросетях.

Основная логика пути читателя:

**попробовал → начал пользоваться → решает реальные задачи → доверяет более сложные задачи → строит свою систему работы с ИИ.**

Новый гайд должен выполнять хотя бы одну из трёх функций:

1. Закрывать конкретный бытовой или рабочий поисковый запрос.
2. Переводить читателя на следующий уровень использования ИИ.
3. Усиливать существующий тематический кластер и внутреннюю перелинковку.

Если материал не выполняет ни одну из этих функций, публиковать его только ради количества не нужно.

# 3. Категории

Используем текущие категории каталога:

- Для жизни
- Документы и информация
- Работа и деньги
- Учёба и семья
- Проверка и безопасность

# 5. Следующий пакет из трёх гайдов

Публиковать следующим пакетом:

## 1. Как сравнить два товара перед покупкой с помощью нейросети

- Ступень: 1
- Категория: Для жизни
- Интент: «как сравнить товары с помощью нейросети»
- Смысл: характеристики → реальные различия → за что переплата → какой вариант подходит конкретному человеку.
- Обязательные блоки: критерии выбора, готовый промпт, пример сравнения, маркетинговые характеристики, слабые места, проверка актуальных цен и спецификаций.
- Иллюстрации: hero + сравнение двух товаров + итоговая схема выбора.

## 2. Как разобраться в инструкции к технике с помощью ИИ

- Ступень: 1
- Категория: Документы и информация / Для жизни
- Интент: «как понять инструкцию с помощью нейросети»
- Смысл: фото страницы или PDF → конкретный вопрос → простое объяснение.
- Обязательные блоки: загрузка инструкции, поиск нужного раздела, ошибка на дисплее, пошаговая настройка, контроль того, что ИИ отвечает по документу.
- Безопасность: газ, электричество, давление, автомобиль и другие опасные системы — только объяснение инструкции и понимание, когда нужен специалист.
- Иллюстрации: hero + инструкция → простые шаги + граница «сам / специалист».

## 3. Как вести большой проект с помощью нейросети: от идеи до результата

- Ступень: 2
- Категория: Система работы
- Интент: «как использовать нейросеть для проекта»
- Смысл: не отдельный запрос, а один проект, который длится несколько недель.
- Примеры: ремонт, переезд, семейный праздник, обучение, запуск небольшого дела.
- Обязательные блоки: цель, этапы, ограничения, постоянный контекст, журнал решений, изменение условий, сводка, следующий шаг, еженедельная ревизия.
- Иллюстрации: hero + хаос → план + схема «цель → этапы → решения → следующий шаг».

Порядок публикации пакета:

**покупка → техника → большой проект.**

Первые два материала дают понятный бытовой поисковый вход, третий переводит пользователя на Ступень 2.

# 6. Целевой размер библиотеки

Первый ориентир: **50–55 сильных гайдов**.

Текущая база: 36.

До первого рубежа добавить примерно 15–19 материалов:

- 6–8 в Ступень 2;
- 5–6 бытовых;
- 3–4 семейных;
- 2–3 материала по безопасности.

После этого не продолжать массовое производство автоматически.

Следующий этап развития должен идти по данным:

- показы в Google Search Console и Яндекс Вебмастере;
- поисковые запросы;
- позиции;
- CTR;
- внутренние переходы;
- страницы, которые получают органический трафик;
- кластеры, в которых уже появляется поисковая видимость.

Расширять победителей, а не библиотеку вообще.

---

# 7. SEO-кластеры после 50 гайдов

Когда библиотека приблизится к 50 материалам, создать отдельные индексируемые посадочные страницы вместо новых фильтров каталога:

- `/guides/dlya-zhizni/`
- `/guides/rabota-i-dengi/`
- `/guides/dokumenty/`
- `/guides/semya-i-obuchenie/`

Каждая страница должна содержать:

- собственный Title и Description;
- короткое введение под поисковый интент;
- тематическую подборку гайдов;
- логичный порядок чтения;
- внутренние ссылки между материалами кластера.

---

# 8. Что не развивать

Не делать основой библиотеки:

- «100 лучших промптов»;
- «50 способов использовать ИИ»;
- еженедельные рейтинги нейросетей;
- общие статьи «что такое искусственный интеллект»;
- новости каждой новой модели;
- материалы про API, MCP, агентные системы и разработку, если они не решают понятную задачу аудитории сайта.

Новости и функции быстро устаревают. Ядро библиотеки — задачи человека.

---

# 9. Редакционный принцип

Каждый новый материал проверять вопросами:

1. Какую конкретную проблему человек решает после прочтения?
2. Для какой ступени он нужен?
3. Не дублирует ли существующий гайд?
4. С каким существующим материалом его нужно связать внутренней ссылкой?
5. Есть ли у темы самостоятельный поисковый интент или сильная роль в маршруте?
6. Какие реальные примеры нужны вместо абстрактных объяснений?
7. Где нужно предупредить о границах доверия ИИ?
8. Есть ли hero + минимум 2 смысловые inline-иллюстрации?
9. Соответствует ли текст `VOICE-SERGEY.md`?
10. Делает ли новый гайд библиотеку глубже, а не просто больше?

# 10. Рабочая модель публикации

Продолжать выпуск пакетами по 3 гайда, если материалы логически готовы.

Для каждого гайда:

1. Определить ступень, категорию и поисковый интент.
2. Подготовить и отредактировать текст в голосе Сергея.
3. Проверить факты и актуальные утверждения.
4. Создать hero + минимум 2 inline-иллюстрации через imagegen.
5. Пройти Content / SEO / Humaniser / Illustrations / Preflight.
6. Сделать отдельный commit.
7. После подготовки пакета выполнить один push.
8. После публикации проверить live URL, каталог, sitemap, внутренние ссылки и индексируемость.

Главный принцип: **не гнаться за количеством. Строить библиотеку, в которой следующий полезный материал логично продолжает предыдущий.**
