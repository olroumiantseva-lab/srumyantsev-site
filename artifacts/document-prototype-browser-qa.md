# Browser QA статического прототипа

Дата: 2026-08-18

## Проверенная версия

- Ветка: `feature/document-prototype`
- Только локальные HTML/CSS/JS и моковые данные.
- Supabase, OpenAI, Cloudflare, оплата и Яндекс.Метрика не подключены.

## Автоматическая browser-проверка

Команда:

```text
node scripts/test-document-prototype-browser.mjs
```

Результат:

```text
PASS: 5 routes × mobile/desktop, no overflow/external requests/console errors; mock flow, validation, 3 follow-ups and delete verified
```

## Что проверено

- прямое открытие с HTTP 200:
  - `/tools/document/`;
  - `/tools/login/`;
  - `/tools/document/app/`;
  - `/tools/document/result/`;
  - `/tools/document/history/`;
- viewport 390×844 и 1440×1000 для каждого URL;
- ровно один `h1` на каждом экране;
- отсутствие горизонтального overflow;
- видимые кнопки, поля и textarea высотой не меньше 48 px;
- отсутствие ошибок JavaScript и ошибок browser console;
- отсутствие внешних сетевых запросов;
- полный моковый путь landing → login → app → result → history;
- ошибка при пустом email;
- success-state демонстрационного входа;
- четыре цели разбора, отмеченные по умолчанию;
- точные подписи четырёх целей и отсутствие отдельной цели «Что делать дальше»;
- ошибка при пустом тексте документа;
- переход к структурированному результату;
- наличие блока «Что нельзя определить из документа»;
- открытые основные блоки и существенные риски, свёрнутые второстепенные блоки;
- три уточняющих вопроса, нулевое списание разборов и блокировка четвёртого;
- подтверждение удаления и исчезновение карточки истории.
- отсутствие фрагментов документа, результата и лишнего статуса в карточках истории.

## Визуальная проверка

Просмотрены полноразмерные снимки landing на mobile и desktop, результата после трёх уточнений и истории после удаления. Текст не обрезается, главные действия заметны, карточки читаются последовательно, интерфейс не напоминает чат.

## Проверка изоляции

Поиск по `tools/` не нашёл подключений или упоминаний runtime-интеграций Supabase, OpenAI, Cloudflare, Метрики и платёжных скриптов. Существующие экспортированные страницы, глобальный CSS, CNAME и схема публикации не изменялись.

## Зафиксированные пользовательские решения

1. В форме используется цель «Что мне нужно сделать»; блок результата называется «Что делать дальше».
2. Сразу показаны четыре основные цели, ещё пять находятся под «Показать ещё варианты».
3. Основные блоки результата открыты. Второстепенные длинные блоки сворачиваются. Существенные риски открыты.
4. История показывает только нейтральное название, тип и дату; фрагментов документа и результата нет.

## Решение, отложенное до следующих этапов

После CTA лендинга прототип ведёт во вход, потому что оплаты пока нет. На этапе подключения оплаты потребуется зафиксировать точную последовательность checkout → success → письмо → вход.
