## Полный прогон v3

20/20 результатов сформированы и сохранены в `product_runs`.

Два внешних HTTP-вызова достигли клиентского timeout, но соответствующие генерации были завершены backend и появились в БД. Результат не потерян.

Автоматические stop-checks по 20 результатам:

- формы `работал(а)`, `обратился(лась)` и аналогичные: 0;
- неподтверждённые угрозы `вы нарушили закон / будете отвечать`: 0;
- безусловное утверждение права на возврат при неизвестных условиях: 0;
- дублирование `Тема:` внутри `final_text`: 0.

Один матч фразы `нарушений не установлено` оказался корректным пересказом прямо указанной пользователем позиции банка, а не выводом сервиса.

## Найденные дефекты

### v1 → v2

1. Машинные формы `обратился(лась)`, `работал(а)`, `готов(а)`.
2. Лишняя поведенческая рекомендация в `cautions` (`не подписывайте акт`) вместо проверки данных.
3. Возможный повтор строки `Тема:` внутри `final_text`.

Исправлено: нейтральная грамматика, `cautions` только как проверки, отдельный `subject` без дублирования темы.

### v2 → v3

1. В ответе на претензию встречалась слишком окончательная формулировка о наличии/отсутствии нарушения.
2. При возврате товара с недостаточными данными текст мог звучать так, будто право на возврат уже установлено.
3. При неизвестном содержании пункта договора модель могла попросить адресата «учесть положения пункта».

Исправлено: позиция отправителя вместо самостоятельного юридического вывода; запрос о возможности/порядке вместо выдуманного права; запрет толкования неизвестных документов.

### v3 → v4 → v5

В полном прогоне остался один мягкий дефект: неизвестный пользователю `п. 7.3` мог попасть в recipient-facing текст. В v4 добавлена детерминированная очистка ссылок на неизвестный пункт, но точечный тест выявил остаточную фразу `учитывать его содержание`.

В v5 очистка расширена на всю фразу, связанную с неизвестным пунктом или его содержанием.

Финальный точечный тест v5:

- в `final_text` остаются только подтверждённые факты: задержка работ, требование объяснить причины и назвать новую дату;
- `п. 7.3` и ссылка на его неизвестное содержание отсутствуют в адресном тексте;
- в `cautions` остаётся корректная проверка: сверить содержание пункта перед отправкой.

## Негативная матрица API

Проверено:

- отсутствует обязательный адресат → HTTP 400;
- неизвестный tone → HTTP 400;
- ввод > 12 000 символов → HTTP 400;
- запрос с неразрешённого Origin → HTTP 403;
- превышение бесплатного лимита → HTTP 429 (подтверждено при массовом прогоне);
- попытка открыть secure result с невалидными `order_id/token` → HTTP 400, результат не раскрывается.
