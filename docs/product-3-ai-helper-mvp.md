# Продукт №3 — «Мой ИИ-помощник»

Статус: MVP specification
Дата: 2026-09-16
Цена релиза: 1 490 ₽
Рабочий URL: `/tools/ai-helper/`
Рабочий product_id: `ai_helper_1490`

## 1. Что продаём

Не набор промптов и не PDF. Пользователь за одну сессию собирает постоянного ИИ-помощника под одну повторяющуюся задачу.

Результат продукта — персональная рабочая инструкция для нейросети + правила проверки + 3 готовых стартовых запроса. Конфигурацию можно вставить в ChatGPT, Claude, Алису, Gemini или другой текстовый ИИ.

Обещание MVP:

> За 60 минут настроить одного ИИ-помощника под реальную повторяющуюся задачу — так, чтобы не объяснять всё заново в каждом новом чате.

## 2. Для кого

Человек уже пользуется нейросетью хотя бы эпизодически, но:

- каждый раз заново объясняет контекст;
- получает ответы разного качества;
- хранит удачные промпты бессистемно;
- хочет повторяемый результат без изучения сложных настроек.

Не обещаем автономного агента, интеграции с почтой/CRM или работу без участия человека.

## 3. Пять сценариев MVP

1. **Письма и ответы** — деловая/личная переписка, тон, структура, границы.
2. **Документы и сложные тексты** — объяснение, извлечение требований, вопросы, проверка выводов.
3. **Посты и тексты** — черновики, структура, собственный стиль, редактура.
4. **Встречи и задачи** — подготовка вопросов, итоги, поручения, следующие шаги.
5. **Заметки и порядок** — превращение сырого материала в структуру, списки и решения.

Пользователь выбирает только один сценарий за одну покупку.

## 4. Пользовательский путь

### Экран 0. Лендинг

Цель: объяснить результат, а не технологию.

CTA: `Настроить своего помощника — 1 490 ₽`.

До оплаты пользователь видит 5 сценариев и пример итоговой конфигурации.

### Экран 1. Выбор задачи

Вопрос: `Для чего вам нужен помощник чаще всего?`

Один из 5 сценариев. Дополнительно короткое поле: `Опишите задачу своими словами`.

Результат шага: `scenario`, `task_description`.

### Экран 2. Контекст

Собираем только то, что реально влияет на ответы:

- кто пользователь / в какой роли действует;
- с кем или с чем работает;
- что обычно получает на входе;
- чего хочет на выходе;
- чего помощник не должен делать.

Результат: `context`, `input_type`, `desired_outcome`, `forbidden_actions`.

### Экран 3. Как должен отвечать

- кратко / подробно;
- нейтрально / тепло / делово;
- списком / абзацами / таблицей;
- задавать уточняющие вопросы или сначала делать черновик;
- что обязательно выделять отдельно.

Результат: `tone`, `detail_level`, `output_format`, `clarification_mode`, `must_include`.

### Экран 4. Пример хорошего результата

Пользователь может вставить 1 пример текста/результата, который ему нравится. Поле необязательное.

Также спрашиваем: `Что обычно раздражает в ответах нейросети?`.

Результат: `good_example`, `bad_patterns`.

### Экран 5. Правила надёжности

По умолчанию включены:

- не придумывать факты, которых нет во входных данных;
- отмечать предположения;
- сообщать, если данных недостаточно;
- отдельно перечислять то, что нужно проверить;
- для закона, здоровья, денег и актуальных данных — не выдавать предположение за установленный факт.

Пользователь может добавить своё правило.

Результат: `verification_rules`, `custom_rule`.

### Экран 6. Проверочный прогон

Пользователь даёт одну реальную мини-задачу.

Сервис строит черновой ответ уже по собранной конфигурации и задаёт один вопрос:

`Что здесь нужно изменить, чтобы помощник отвечал так, как вам удобно?`

Пользователь выбирает:

- всё подходит;
- сделать короче;
- сделать подробнее;
- изменить тон;
- добавить своё замечание.

Результат: `test_input`, `test_feedback`.

### Экран 7. Итог

Платный результат содержит:

1. **Кто ваш помощник** — одно короткое описание роли.
2. **Основная инструкция** — готовый блок, который можно вставить в новый чат/проект.
3. **Как им пользоваться** — 4–6 правил для человека.
4. **Что помощник должен проверять** — персональные правила надёжности.
5. **Три готовых старта** — типовые первые запросы под выбранный сценарий.
6. **Контроль качества** — короткий чек-лист перед использованием важного ответа.
7. Кнопки: `Скопировать инструкцию`, `Скачать TXT`, `Сохранить как PDF`.

## 5. Что НЕ входит в MVP

- подключение к Gmail, Telegram, CRM, календарю;
- автоматические действия от имени пользователя;
- постоянная серверная память разговоров;
- несколько помощников за одну покупку;
- загрузка базы знаний из десятков файлов;
- подписка;
- мобильное приложение;
- отдельный аккаунт/пароль.

## 6. Архитектура

Используем паттерн продукта №2:

`landing → payment → secure access → wizard → generation → secure result`

Без magic-link в основном пользовательском пути.

### Product

`ai_helper_1490`

Цена production: `149000` коп.

### Предлагаемые Edge Functions

- `ai-helper-payment` — либо общий `create-payment`, если поддерживает новый product_id;
- `ai-helper-save-step` — опционально, если сохраняем прогресс по шагам;
- `ai-helper-generate` — собирает финальную конфигурацию и тестовый ответ;
- `ai-helper-success-access` — secure token после Robokassa;
- `ai-helper-secure-result` — выдача результата по token hash.

### Таблицы

`ai_helper_sessions`

- id uuid PK
- payment_order_id bigint
- status text (`draft`, `ready`, `completed`)
- scenario text
- answers jsonb
- result jsonb
- created_at timestamptz
- updated_at timestamptz

Secure-token таблицу можно переиспользовать по общему паттерну либо создать отдельную `ai_helper_access_tokens`.

## 7. Формат AI-результата

Строгий JSON, без свободного HTML:

```json
{
  "assistant_name": "Помощник по деловым письмам",
  "role_summary": "...",
  "master_instruction": "...",
  "usage_rules": ["..."],
  "verification_rules": ["..."],
  "starter_requests": ["...", "...", "..."],
  "quality_checklist": ["..."]
}
```

`master_instruction` должна быть самодостаточной: пользователь может скопировать только её и уже получить полезный результат.

## 8. Критерии качества MVP

Сценарий считается успешным, если:

- итог явно учитывает ответы конкретного пользователя;
- инструкция не выглядит универсальным шаблоном;
- нет обещаний автономности, которой продукт не даёт;
- инструкция понятна человеку без технических терминов;
- минимум одно пользовательское ограничение отражено в `master_instruction`;
- правила проверки присутствуют всегда;
- три стартовых запроса различаются по задаче, а не перефразируют друг друга.

Перед production: минимум 15 regression-сценариев — по 3 на каждый из 5 типов помощника.
